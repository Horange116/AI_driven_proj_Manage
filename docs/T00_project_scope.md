## 1. 项目一句话目标

基于 PT9L 项目的真实历史文档，建设一套可运行的智能文档复核系统：先把 DHF / DMR 文档解析成结构化数据，再建立知识层和异常检测能力，最终输出带证据链的 findings，并提供复核员可用的 Web 界面、导出结果和成本-精度报告。

## 4. 首批 finding 类型

第一批优先做“确定性强、能形成证据链、对文档复核价值高”的问题。

| 类别 | finding 类型 | 优先级 | 推荐处理层级 |
|---|---|---|---|
| 文件级 | 完全重复文件：不同文件名但 hash / MD5 相同 | 高 | L0 规则 |
| 文件级 | 空文件、解析为空、正文过短 | 高 | L0 规则 |
| 文件级 | 文件扩展名、内容类型、目录阶段不匹配 | 中 | L0 / L1 |
| 内容级 | 占位符、模板残留、未填写字段 | 高 | L0 / L1 |
| 内容级 | 明显乱码、OCR 质量过低 | 中 | L0 / L1 |
| 内容级 | 异常日期、版本号缺失或格式异常 | 中 | L1 |
| 参数级 | 同一参数跨文件取值冲突 | 高 | L1 / L2 |
| 版本级 | 多个 V1.0 并存但缺少变更说明 | 高 | L1 / L2 |
| 追溯级 | 需求、风险、验证、输出之间断链 | 高 | L2 / L3 |
| 类级模式 | 同类文档大面积模板污染或复制痕迹 | 中 | L1 / L3 |

## 5. 分层处理边界

先把确定性工作做成稳定工程能力，再引入 LLM 和多智能体。

| 层级 | 适合处理 | 不适合处理 |
|---|---|---|
| L0 纯规则 | hash 重复、文件大小、空文本、占位符、格式检查 | 需要语义判断的问题 |
| L1 结构化规则 + 知识层查询 | 参数抽取、版本对齐、同名实体聚合、简单冲突 | 证据不足或语义复杂的问题 |
| L2 LLM 单点判断 | 单文件复杂异常、参数语义归一、疑似冲突解释 | 大规模全量扫描 |
| L3 多 Agent 协作 | 跨文档追溯断链、复杂冲突、多证据综合判断 | 可由规则稳定解决的问题 |

结论：T01-T05 先建设数据底座；T06-T08 先形成 finding 生产能力；T09 再引入多智能体分级路由。

---

## 6. 阶段边界

### W1 / W2 基础工程

必须先完成：

- 文档资产盘点
- 文件解析基线
- 统一结构化 JSON
- 知识层 schema
- 索引与查询接口

这些阶段的重点是稳定、可重复、可追溯，不追求复杂推理。

### W3 / W4 检测能力

开始输出 findings：

- 单文件异常检测
- 跨文档关联检测
- finding 证据链格式

这些阶段的重点是 precision / recall、证据可验证、规则和知识层配合。

### W5 / W6 系统化交付

做成可使用系统：

- 分级路由
- 多智能体架构
- 端到端 pipeline
- Web 复核界面
- 导出、dashboard、复盘材料

这些阶段的重点是成本控制、人工复核效率和最终演示。
